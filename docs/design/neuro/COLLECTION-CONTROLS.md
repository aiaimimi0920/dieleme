# 采集控制与阶段筛选改版

## 结果与边界

已完成 Crow 源码修改、离线验证和新版 Windows EXE 构建。
**没有部署、重启或重新配置 NAS / PC2，没有替换或结束当前运行中的观察台。**

## 界面变化

- 左侧三个阶段入口合并为一个“采集”，左下角继续固定“设置”。
- 删除“运行细节”按钮及可折叠诊断卡，总览始终为五栏。
- 第一栏：当前运行状态、单个“开始采集 / 暂停采集”切换按钮、独立“重启”按钮。
  普通开始只解除操作员暂停，不清除挑战标记，不冒充认证成功。
- 第二栏：当前是否处于挑战中。读取实际 solver 和分阶段挑战状态，而不是历史触发率。
  挑战中可点击“认证”，沿用 PC1 主动人工认证流程；无挑战时禁用认证按钮。
- 第三至五栏：商品链接、商品详情、商品分析的唯一商品数，以及约一分钟的实际增量。
  不再显示链接出现次数、待处理 / 失败 / 阻塞等常驻二级计数。
- 地区面板增加“链接 / 详情 / 分析”三个单选按钮，切换时保留地区选择并重置分页。
- 设置页保留原有浏览与编辑状态；重启授权只存在当前窗口内存，切换 API 地址时清除。
- 保留断连和旧快照警告；为地区、总览和 API 切换增加旧响应隔离，避免快速切换后串数据。

窗口仍为 1120×760，侧栏 186px、折叠 52px、顶栏 50px，保持上一轮 Loom 对齐尺寸。

## 统计与筛选口径

| 项目 | 口径 |
| --- | --- |
| 商品链接总数 | 唯一商品，不是不同排序、地区或轮次中的链接出现次数 |
| 商品详情总数 | 已捕获详情的唯一商品，包括等待分析、分析失败 / 阻塞和已完成分析 |
| 商品分析总数 | 当前已完成分析的唯一商品 |
| 链接筛选 | 已发现链接，尚未完成详情采集；保留详情失败 / 阻塞项 |
| 详情筛选 | 已完成详情采集，尚未完成分析；保留分析失败 / 阻塞项 |
| 分析筛选 | 已完成分析；这是采集流程末阶段，没有下一阶段 |

三个列表在数据库层互斥，并在过滤后计算唯一商品总数和分页。
再分析会把商品移回“详情”；保留的历史 final JSON 不会把当前待分析商品误判为完成。
地区徽章仍表示该阶段在该地区的整体采集进度，与列表的互斥分组不是同一个统计量。

分钟增量是当前计数减去约一分钟前的有效快照，不是数据库逐条完成事件的精确时间窗口。
采样窗口为 60 至 75 秒，以容忍轮询和网络延迟，悬停会显示实际采样秒数。
首次打开、切换 API 或长时间中断后显示“等待分钟采样”；短间隔手动刷新不折算成分钟。
重新入队等原因造成计数减少时，会显示负数及“数量回退”，不会伪造为正增长。

## 重启实现

已实现桌面确认 -> NAS 持久请求队列 -> PC2 主机控制器 -> 执行回执的代码链路。
它与已有的认证恢复状态接口分离，不会把“标记正在重启”误作真正的进程重启。

- 操作员和 PC2 控制器使用两个不同的令牌；未配置、令牌错误或控制器离线时不可执行。
- 重启只针对经过 Compose 标签及容器 ID 校验的 8 个采集 Worker。
- 不重启整台 PC2、Docker 服务、NAS、浏览器求解器或 PC1 认证浏览器，不删商品数据。
- 请求持久化并去重；并发合并的请求 ID 也会保留关联，避免丢失响应后重试触发第二次重启。
- 领取后不自动重复执行；只重试回执提交。结果不明显示“未确认”，不会显示成功。
- 只有原容器 ID 均重新启动且健康检查通过，才返回 Worker 就绪；不宣称商品采集已成功。
- 重启受理时只解除一次操作员暂停，延迟回执不会覆盖之后新的暂停操作。

部署前提、令牌文件、持久数据目录、HTTP 风险及 opt-in 控制器命令见
[重启通道接入说明](../../runbooks/collection-engine-restart.md)。本轮没有执行其中的启动命令。
