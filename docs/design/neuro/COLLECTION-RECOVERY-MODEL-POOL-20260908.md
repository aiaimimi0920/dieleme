## 一、链接采集为什么停了

诊断时，seed 容器一直健康、循环仍在执行，队列还有 28,123 个待扫进度，并不是队列清空或进程退出。停止前的运行仍能返回页面和商品条目。

真正边界是：站点挑战明确拒绝自动处理后，底层产生了 `failure_reason=manual_required`；PC2 执行接口和子进程 IPC 却只传递成功/失败布尔值，上层丢失了“必须人工接管”的终止原因，继续轮换页面。NAS 因而持续显示 `captcha_solver/running`，seed 每轮都在暂停门禁处返回。

已修复：

- 保留终止原因，经过本地执行和 spawned child IPC 传回控制循环。
- 终止失败不再进入页面轮换分支，改为调用现有人工认证上报接口。
- 上报暂时失败时持久化待上报状态，按间隔重试，不重启自动处理。
- 上报携带采集范围与 challenge ID，避免旧请求覆盖新挑战。
- 保留既有认证完成后的清理与确认顺序；没有修改滑块轨迹或绕过真实认证。

已通过现有 NAS 接口把本次 seed 挑战转换为人工等待。最终实时状态：

```text

seed.manual_required = true
```

四个分析容器均健康，但连续批次都是 `detail_worker_llm_unavailable`，`attempts=0`、`completed=0`。失败发生在模型预检门禁处，没有开始领取商品进行分析。

## 三、动态模型池已实现的规则

- 从当前配置服务发现模型，在任何测试请求前排除 GPT、Codex、OpenAI 推理系列；名称明确的非文本路由也进行过滤。
- 新增 5 条固定资料提取用例及人工预设答案，覆盖成交价、万元换算、面积、未成交、缺失信息。
- 每例精确匹配得 1 分，否则 0 分；只忽略首尾空白，不进行模糊评分或模型裁判。
- 按至少 4/5 合格实现；从合格路由中选得分最高的最多 5 个，同分参考测试耗时。
- 池内轮换使用；调用失败后冷却该路由，并尝试其他合格路由。
- 四个 worker 共享私有资格状态与扫描租约，避免四份重复测试。
- 每批最多 8 个模型、40 次测试；批次间隔至少 120 秒；失败路由至少间隔 15 分钟重新测试；资格有效期 24 小时。
- 模型目录会动态增减，进度改为按模型 ID 记录，优先测试未测路由，避免反复从目录前八项开始。
- 资格扫描在后台进行；正常预检不等待整批测试。没有可用模型时不领取商品，处理中全池不可用则沿用恢复原始详情、回退本次尝试次数的路径。
- 资格缓存不是业务数据库：PC2 使用现有共享挂载下的 `/data/datas/model-pool/pool.sqlite3`；现场文件权限为 `0600`，不保存明文 API key。

最新实时证据为：`tested_models=25`、`qualified=[]`，资格记录中没有被排除的 GPT 等路由。目录仍在继续分批检测，尚不能提供“可投入使用的最佳五个模型”名单。

设置界面中的模型值仍是首选配置，不是动态池当前实际路由列表。本次没有新增模型池管理页面。详细规则见 `docs/runbooks/analysis-model-pool.md`。
