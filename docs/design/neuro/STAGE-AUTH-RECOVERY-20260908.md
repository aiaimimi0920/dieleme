## 根因

此前的运行检查记录见 `SEED-COLLECTION-STALL-20260908.md`：PC2 的详情数量增加，但链接列表页仍出现验证页面。

原实现有两个独立问题：

1. NAS 使用详情捕获数量增长结束整个认证恢复任务，没有区分链接与详情；因此“详情恢复”被误当成“链接也恢复”。
2. 认证入口和完成清理没有始终携带阶段信息。尤其链接探测成功通知未明确声明 `scope=seed`，可能按全局最近请求选择错误阶段。

链接、详情可能复用同一登录会话，但不能假定两个页面入口的挑战状态相同。此次按业务阶段独立展示与确认，不是强制要求每次完成两次挑战。

## 新交互

中控台原挑战卡片变为紧凑的两行：

| 阶段 | 独立显示 | 操作 |
| --- | --- | --- |
| 链接采集 | 待认证 / 未报告挑战 / 状态未知 | 认证 |
| 详情采集 | 待认证 / 未报告挑战 / 状态未知 | 认证 |

- 两个入口不因“未报告挑战”、未知状态或手动暂停而禁用。
- 弹窗仍只有 **打开挑战页面**、**已完成挑战** 两个按钮，不增加二级标题。状态行标明当前阶段。
- 链接入口使用对应列表页；详情入口使用对应商品详情页，没有目标时尝试取一个待采详情商品，不会回退到链接列表页冒充详情认证。
- 在两阶段之间切换会保留各自的页面、请求 ID 和待确认回执；不能用另一阶段的任务 ID 替换当前任务。
- Cookie 导出和导入仍然串行，因为 PC1 / PC2 当前使用共享浏览器会话。另一阶段正在交接时会提示稍后重试，不会覆盖正在传输的快照。

## 完成判定与安全性

- `scope`、目标 URL、挑战 ID、恢复 ID、快照摘要沿 PC1 → NAS → PC2 传递。
- NAS 只解除选定阶段的暂停；新挑战 ID 不匹配时拒绝完成，保留另一阶段状态和正在运行的处理流程。
- **链接认证**：PC2 导入后，新建仅属于探测的页面，实际访问指定列表，要求存在合法列表数据且无登录 / 挑战标记。允许合法空列表或全部为已知商品，不要求唯一链接数量增长。探测不会执行验证码解题或滑块操作，只关闭它自己创建的探测页。
- **详情认证**：Cookie 接收确认后，基线重新采样；需要后续详情捕获数量增长，且详情阶段没有新的挑战，才能完成。链接阶段的挑战不阻止详情完成。没有新详情可采或人为暂停时，不会伪造成功，验证有超时提示。
- PC1 验证详情会话不再强制要求链接样本也通过。
- 保留不可变快照、摘要校验、重复提交幂等、过期任务拒绝和 15 分钟桌面轮询上限。
- 分阶段能力需要 NAS v2 接口和最近上报能力的 PC2 接收端同时就绪；旧接收端的 Cookie 导入回执不能满足新阶段协议。
- 没有新增数据库表、全库统计查询、数据清理、重置地区或重跑全量任务。
